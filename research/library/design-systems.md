## Fluent 2 Design System

| 項目 | 内容 |
| --- | --- |
| 種別 | 現行の公式資料 |

| 分野 | デザインシステム、原則、レイアウト、アクセシビリティ |
| 無料で読めるか | 公式サイトは無料 |
| 優先度 | 高。編集メモであり、Core の推奨値ではない |
| URL | https://fluent2.microsoft.design/ |
| 原則 | https://fluent2.microsoft.design/design-principles |

このカードはシリーズの再現仕様ではない。`research/analysis/` に Fluent の分析ファイルは、この作業時点で無かった。

### 何について書かれているか

ホームは、デザイン（Figma の UI キット）、開発、Web / iOS / Android / Windows のコンポーネントを案内している。原則ページを開いた。原則は、意思決定を揃える価値観だ、と前書きにある。四つある。

- Natural on every platform。装置に合い、既に知っているものに乗せる。レイアウトは画面サイズとプラットフォームを意識する、と機能面に書く。
- Built for focus。流れを切らず、視覚的な雑音を減らす。
- One for all, all for one。能力と視点の幅を、設計の早い段階から含める。
- Unmistakably Microsoft。色、音、イラスト、アイコンなどの署名的な体験で、製品同士が一つの Microsoft に感じられるようにする。

原則ページは、ネイティブの部品とパターンを再利用し、署名的な体験に労力を集中する、とも書く。そこに割合の文がある。Microsoft 製品の方針であり、andm の割合トークンではないので、数値は写さない。レイアウト、文字、色、モーションのトークン値も、このカードでは写さない。各ページを開いたときに分析へ残す対象である。

### UIデザインシステムとの関連

複数プラットフォームで「慣れたものに乗せる」と「一つのブランドに見える」を同時に原則へ書いている例である。Windows と Web で部品を揃えるときの比較対象になる。シリーズ化は、この文献カードとは別の決定である。

### なぜ読む価値があるか

原則が短く、プラットフォーム適応とブランドの署名を分けて読める現行資料だからである。寸法は原則ページには無かった。

### 確認

確認済みはホームと原則ページ。レイアウトやコンポーネントの本文は未読。

### 確認

確認済みは「What is Carbon」のページ。トークン JSON はこの作業では開き直していない。

### 何について書かれているか

ホームを開いた。GOV.UK と一貫した政府サービスを作るためのスタイル、コンポーネント、パターンである。他チームの調査と経験を再利用し、同じ仕事を繰り返さない、と書く。スタイルはレイアウト、文字、色、画像。コンポーネントはフォーム、ナビゲーション、パネル、表など。パターンは、氏名や住所の入力、フォーム、アカウント作成のような共通タスクである。

ホームは、Government Design Principles と GOV.UK Service Manual に沿うこと、スタイルガイドとコンテンツのガイダンスに沿うこと、アクセシビリティ戦略を持つこと、を述べる。コミュニティからの研究と実装を取り込み、GDS のチームが維持する。2025 年 6 月からのブランド更新に合わせて Frontend を複数版出している、とホームにある。新しい部品には Trial などのライフサイクルがある、とも書く。

部品の寸法と色の値は、このカードには写さない。シリーズの再現対象にしていない。

### UIデザインシステムとの関連

スタイル、部品、パターンを分け、部品に成熟度を付け、政府の原則とサービスマニュアルの外側にシステムを置いている。公共系の文書構成の比較対象として開く。andm の見た目へ数値を輸入する対象ではない。

### なぜ読む価値があるか

「再利用できるパターン」と「すべてのサービスを同じピクセルにする」を、原則側が明確に分けている（一貫だが均一ではない）。部品ライブラリの運用を、ブランドの刷新と一緒に文書化している現行例でもある。

### 確認

確認済みはデザインシステムのホームと、原則ページ。個別コンポーネントのガイダンス本文は未読。

日本語で、行政向けに、デザイン言語とコンポーネントとアクセシビリティを一つの公開サイトに置いている現行資料だからである。WCAG や JIS との関係は、分析と [標準](standards.md#jis-x-8341-3) の両方を見て判断する。
