## 思想・概念

本文が取れたページから要約する。数値の規則は下の節に残し、ここは理念だけ。

トップページは、デザイン言語、UI コンポーネント、ユーザビリティとアクセシビリティを踏まえたガイドラインからなるデザインアセットだと書く。対象は行政機関や公共性の高い組織のウェブサイト、ウェブアプリ、オンラインサービス。標榜するのは、デジタル庁のミッション「誰一人取り残されない、人に優しいデジタル化を。」への寄与。

「デザインシステムとは」は、準拠を機械的に生成する規約ではなく、デザインの考え方や枠組みとアクセシビリティを掛け合わせた仕組みだと書く。制作を効率化し、設計や試行に時間を割けるようにするためのもの、ともある。追求する理念は次の3つ。

- アクセシビリティファースト。ウェブの特性を生かすため、アクセシビリティを最優先に置く。WCAG などのガイドラインを取り込み、これを使って作るとアクセシビリティに優れた成果物が得られやすくなることを目指す。
- 行政機関にとっての高い汎用性と利便性。特定のブランドや単一のサービスのためではない。プリミティブな情報要素の組み合わせで部品を作り、サービスごとのスタイルガイドへ矛盾なく落とせるようにする。行政の手続きを想起しやすい作例で、活用を促す。
- 継続的かつ持続可能な改善。規格と閲覧環境の変化、用途やニーズの変化に寄り添う。この意志を「β版」表示に込めている、と本文にある。

アクセシビリティのページは、最優先事項として作成されている、と繰り返す。注意しているのは、色のコントラスト、フォントサイズ、キーボードとフォーカス、ターゲットサイズ、操作に対応したインタラクション、動きのあるオブジェクト、内容量の増減を踏まえた外観。一方で、サイト固有のコンテンツのアクセシビリティは制作者側が確保する、とも書いてある。デザインシステムが達成できるのは、考慮すべきアクセシビリティの一部である。

基本デザイン（foundations）は、サービスに独自の外観と雰囲気を与える視覚的特徴を作るものだと書く。サービスのニーズに合わせてスタイルを選び、変える。

## 考え方（読めた範囲）

トップページは、デザイン言語、UI コンポーネント、ガイドラインからなるデザインアセットだと書く。対象は行政機関や公共性の高い組織のウェブサイト、ウェブアプリ、オンラインサービス。基本デザインは、サービスごとの見た目を作るための視覚的特徴で、ニーズに合わせて選ぶ、と foundations にある。

## color

本文にあるルール:

- キーカラーは同じ色相の階調から選ぶ。プライマリー、セカンダリー、ターシャリー、バックグラウンドを含む。
- プライマリーはトーンと、優先される動線（CTA、アクティブ）に使う。主要な背景とのコントラストは少なくとも 4.5:1。
- セカンダリーとターシャリーを背景に隣接する非テキストに使うときは 3:1 以上。テキストに使うときは 4.5:1 以上。
- テキストと背景は常に 4.5:1 以上。枠線やディバイダーなどの非テキストは 3:1 以上。
- リンク色は 4.5:1 以上を保ち、青が伝統的な慣習、と本文にある。青の hex は無い。
- セマンティックカラーは色相を保てばブランドに合わせて調整できる、と本文にある。
- パレットページの本文にある色名: 青、ライトブルー、シアン、緑、ライム、黄、オレンジ、赤、マゼンタ、紫。ニュートラルは白、黒、グレー。
- 本文に出た hex は白 `#FFFFFF` と黒 `#000000` だけ。
- Gray-420 は白に対して 3:1。Gray-536 は白と黒に対して 4.5:1。Gray-600 は黒に対して 3:1。各 Gray の hex は本文に無い。

## typography

- 書体は Noto Sans JP と Noto Sans Mono。システムフォントの使用は禁止していない。フォントファイルは置かない。
- 太さは N = 400（normal）、B = 700（bold）。
- 大きさの目安: 48〜64px は視覚的インパクト。16〜45px は見出しと本文。本文と UI の基準は 16px 以上。14px はフッターや領域が足りないときだけ。14px 未満は原則使わない。
- 読み物の本文の行高は、フォントサイズの少なくとも 1.5 倍を推奨。
- スタイル名はサイズ、太さ、行高をつないだトークン。本文の表から（単位は CSS px と行高%）:

Display は行高 140%、字間 0。Dsp-64 / 57 / 48 の B と N。

Standard は 16px 以上が基本。字間は 0、1%（0.01em）、2%（0.02em）。

| Std-36 | 36 | B/N | 140% | 1% |

## radius

角は5段階を目安にし、コンポーネントごとに規定する、と本文にある。小さい図形ほど角丸が強く見える。px の5段階は概要本文に無い。検証不能。

## elevation

- 既定は高さレベル 0。影もシェードも無い面。
- 表現はドロップシャドウとオーバーレイシェード。
- 影のある要素は、背景とのコントラストを影では満たせない。境界を置き、境界と背景で 3:1 以上。
- ほとんどの要素はレベル 0。立体感のある面はレベル 1。Hover で高さを変える部品は、置かれているレベルより少なくとも 1 段上を確保する。
- ダイアログなど浮く部品は少なくとも 2 段上。レベル 0 だけの画面ならレベル 2。レベル 1 のボタンがあるときはレベル 3 以上。
- オーバーレイシェードは、覆う対象のいちばん高いレベルの上に敷き、表面をレベル 0 に戻す。シェード自体は原則クリックできない。
- 影の px や色の式は本文に無い。

## コンポーネント（ボタン）

https://design.digital.go.jp/dads/components/button/ の本文:

- ボタンはアクションかページ遷移。
- 幅はラベルに合わせて伸びる。高さは複数行になるとフォント定義に従って増える。最小幅と最小高さはスタイルごとに定義する、とある。その px は本文に無い。
- ターゲット領域は 44 CSS px 以上。Small と X-Small が 44px 未満のときは上下に余白を足す。Small / X-Small の高さ自体は本文に無い。
- スタイルは3種。塗り（背景が色、ラベルは White）。アウトライン（外周とラベルが色、背景は White）。テキスト（透明で、下線のラベルが色）。
- 重要度の例: 塗りが高、アウトラインが中、テキストが低。色の違いだけでは階層を示せない。境界を変える。
- プライマリーは画面に原則1つ。セカンダリーは同時に原則3つまで。ターシャリー（キャンセル）は原則1つ。
- LTR では進むボタンを右、キャンセルを左。右端ほど重要。モバイルの縦積みは、デスクトップと同じ意味の順。1つだけのときは右端か中央。
- 現行バージョンは国際化対応を含まない。RTL では左右が逆、と本文にある。

## まだ Button 以外を作るときに使うルール

- 本文と UI の字は 16px 以上。14px は例外。14px 未満は原則使わない。
- UI の1行は Oneline（行高 100%、字間 0.02em）。管理画面の表は Dense。
- コントラストはテキスト 4.5:1、非テキスト 3:1。Gray-536 より暗いグレーが白背景の本文を満たす、とパレット本文にある。
- 面の既定はレベル 0。浮くダイアログは、下のボタンがレベル 1 ならレベル 3 以上。
- ボタンのターゲットは 44px 以上。進む操作は右、キャンセルは左。
